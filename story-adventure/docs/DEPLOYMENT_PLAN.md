# AI 互动故事冒险机上线计划

日期：2026-06-22

## 上线目标

先做一个适合社区现场使用的网页版本：

- 孩子扫码打开网页
- 不需要登录
- 不需要输入 API Key
- 不需要数据库
- 玩完整个互动故事
- 输入自己的名字
- 生成故事书
- 导出长图保存到手机

## 第一版不做数据库的原因

现场活动最重要的是简单稳定。

如果不做数据库：

- 故事进度保存在孩子自己的手机浏览器里
- 最终作品通过导出长图保存到手机
- 服务端不保存孩子内容，隐私压力更小
- 部署复杂度低
- 不需要做账号、登录、权限、历史列表

缺点：

- 换手机或清浏览器缓存后，故事找不回来
- 不能做跨设备历史故事
- 不能做作品墙或后台管理

结论：第一版现场活动够用，数据库后置。

## 当前本地版保存方式

本地版：

- 故事状态：浏览器 `localStorage`
- 图片任务：Node 内存任务
- 图片文件：`story-adventure/generated/`
- 最终作品：导出 PNG 长图

这个方式适合本地开发，但不完全适合 Vercel 等 serverless 部署。

## 上线友好版改造

### 必须改

1. 图片不要依赖服务器本地文件保存

当前：

```text
UU 生图 -> 后端保存到 story-adventure/generated/ -> 前端轮询回填
```

上线第一版建议改为：

```text
UU 生图 -> 后端返回 imageUrl/base64 -> 前端保存到 localStorage -> 故事书使用浏览器里的图片
```

这样不依赖服务器磁盘。

2. 图片任务不要依赖长时间后台任务

当前任务制适合本地 Node 长进程。Vercel serverless 可能中断后台任务。

上线第一版建议：

- 前端发起图片生成请求
- 请求完成后直接回填
- 期间显示默认图
- 如果失败，保留默认图
- 不追求“用户离开页面后后台继续生成”

3. 环境变量全部放部署平台

线上必须配置：

```text
OPENAI_API_KEY
OPENAI_BASE_URL
OPENAI_MODEL
IMAGE_API_KEY
IMAGE_BASE_URL
IMAGE_MODEL
IMAGE_SIZE
```

不要把 `.env.local` 提交到 Git。

### 可以保留

- `localStorage` 保存当前故事
- 导出长图 PNG
- 儿童安全 prompt 和安全词检查
- 9:16 手机 UI
- DeepSeek 文本生成
- UU 文生图

## 推荐部署路径

### 方案 A：Vercel

优点：

- 快
- 适合扫码网页
- 配环境变量方便
- 有 HTTPS 域名

风险：

- serverless 不适合本地文件保存
- serverless 不适合长时间后台生图任务

需要先完成“上线友好版改造”。

### 方案 B：云服务器 / 长运行 Node

优点：

- 当前本地任务制基本可以沿用
- 本地文件保存也能用

风险：

- 部署、域名、HTTPS、维护更麻烦
- 现场时间紧，不建议第一版走这个

## 明天执行顺序

1. 检查 Git 当前状态，确认今晚提交存在。
2. 改造图片生成流程，部署版不依赖 `generated/`。
3. 增加部署环境开关，例如：

```text
IMAGE_STORAGE_MODE=browser
```

或直接统一改成前端保存。

4. 本地用手机尺寸测试完整流程。
5. 部署到 Vercel。
6. 在 Vercel 配置环境变量。
7. 线上真机测试。
8. 生成二维码给现场使用。

## 线上真机验收清单

- 手机扫码能打开首页
- 首页、输入页、故事幕基本能在 9:16 一屏内操作
- 输入 3 个字以上能开始
- 第一幕真实调用 DeepSeek
- 第二幕、第三幕能承接前文选择
- 结局不凭空出现前文没有的人名
- 每幕图片能生成或失败兜底
- 结局后能输入孩子名字
- 故事书标题带孩子名字
- 导出长图可保存到手机
- 刷新页面后可继续上次故事
- API Key 不出现在前端源码和浏览器请求参数中
